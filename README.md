# Clinic API

Backend для записи пациентов на приём к врачу. FastAPI + PostgreSQL + SQLAlchemy 2.0 (async).

## Стек

- **FastAPI** — HTTP-слой, автодокументация OpenAPI
- **PostgreSQL 16** — основная БД
- **SQLAlchemy 2.0 (async)** — ORM, работа через `asyncpg`
- **Alembic** — версионирование схемы БД
- **Pydantic v2** — валидация входных и выходных данных
- **Docker Compose** — окружение для разработки

## Архитектура

Три слоя с односторонней зависимостью:

- `api/` — роутеры: разбор HTTP-запроса, перевод доменных ошибок в статус-коды
- `services/` — бизнес-логика, границы транзакции
- `repositories/` — доступ к БД, ничего не знают о HTTP

Сервис не импортирует FastAPI, репозитории не знают о бизнес-правилах.

## Защита от одновременной записи на один слот

**Проблема.** Два пациента могут одновременно нажать «записаться» на один и тот же слот.
Наивная проверка «свободен ли слот» перед вставкой не спасает: между чтением и записью
успевает вклиниться второй запрос, и оба видят слот свободным.

Защита построена на трёх уровнях:

**1. Порядок шагов — `AppointmentService`.** Слот сначала блокируется, и только потом
проверяется его занятость. Обратный порядок бесполезен: проверка вернёт ответ, который
успеет устареть, пока мы идём ставить блокировку.

**2. Блокировка строки — `SlotRepository.get_by_id_for_update()`.** `SELECT … FOR UPDATE`
заставляет второй запрос ждать на уровне PostgreSQL, пока первая транзакция не завершится.
Дождавшись, он видит уже актуальное состояние.

**3. Частичный уникальный индекс — на уровне БД.**
`UNIQUE (slot_id) WHERE status = 'scheduled'` физически запрещает две активные записи на
один слот — даже если данные попадут в базу в обход Service.

**Результат.** Первый пациент получает `201`, второй — `409 Conflict` с понятным сообщением,
а не сырую ошибку целостности(IntegrityError). Транзакция второго откатывается целиком.

## Запуск

```bash
docker-compose up -d
python3.13 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

Документация: http://127.0.0.1:8000/docs
